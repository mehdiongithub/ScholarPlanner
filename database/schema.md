# Database Schema & Entity Relationships

This document outlines the purpose, constraints, indexes, and cascades for the 33 tables in the database.

---

## 1. Core Architecture Pipelines

### Users, Roles & Permissions
- **`roles`**: Defines accessibility levels (`admin`, `employee`, `visitor`).
- **`permissions`**: Granular capability tags (e.g. `users.view`, `scholarships.create`).
- **`role_permissions`**: Many-to-many lookup mapping permissions to roles.
- **`users`**: Customer/Staff credentials (hashes passwords using `password_hash`, stores verification checkpoints, and manages opt-ins).
- **`student_profiles`**: Personal details (biodata, preferences) separated from credentials.
- **`education_records`**: Many-to-one history tracking previous degrees and grades (CGPA).

### Geography Structures
- **`countries`**: Centralized currency, iso standard codes, and dial codes.
- **`states`**: Provinces mapped to countries (seeding Pakistan regions).
- **`cities`**: Major cities mapped to states.

### Scholarships & Matchings
- **`fields_of_study`**: Academic fields (Computer Science, Law, etc.).
- **`scholarship_categories`**: Label tags (Fully Funded, Undergraduate).
- **`scholarships`**: Metadata for opportunities, provider links, deadlines, and publishing statuses.
- **`scholarship_category_map`**: Maps categories to scholarships.
- **`scholarship_eligibility_rules`**: Structured matching criteria (minimum age, maximum age, minimum CGPA, IELTS/TOEFL requirements) used by the matching algorithm.
- **`scholarship_benefits`**: Funding details (tuition coverage, travel stipends) mapped to scholarships.
- **`documents`**: Common check sheets (Passport, CV, recommendation letters).
- **`scholarship_documents`**: Links document requirements to scholarships.
- **`scholarship_sources`**: Reference links to support authenticity.
- **`scholarship_deadlines`**: Supports future recurring timeline logic.
- **`saved_scholarships`**: Student bookmarks mapping.
- **`scholarship_matches`**: Matches generated by the engine, logging scores, engine version, and reasoning metrics.
- **`scholarship_applications`**: Status pipeline (Preparing, Applied, Shortlisted, etc.).

### Notifications Logs
- **`user_preferences`**: Daily frequency toggles.
- **`notification_preferences`**: Per-notification triggers.
- **`notification_logs`**: Outbox history (channels: WhatsApp, Email, Web).

### Billing & Locally localized plans
- **`subscription_plans`**: Localized tiers (Free, Premium) mapping pricing currencies (PKR, INR, USD).
- **`subscriptions`**: Tracking subscription statuses (`active`, `past_due`, `cancelled`).
- **`payment_transactions`**: Logs invoice entries (never stores card numbers or security secrets).
- **`payment_webhook_logs`**: Logs raw webhooks for verification.

### System Audits & Logs
- **`employee_assignments`**: Job dispatch tracking for employees.
- **`audit_logs`**: Administrative histories.
- **`settings`**: Dynamic key-value configuration flags.
- **`contact_messages`**: Contact support logs.

## 2. Integrity & Cascade Rules

### Cascading Deletions (`ON DELETE CASCADE`)
Used on tables where the child records are strictly dependent on the parent record's existence:
- `states.country_id` -> `countries.id`
- `cities.state_id` -> `states.id`
- `role_permissions.role_id` -> `roles.id`, `role_permissions.permission_id` -> `permissions.id`
- `student_profiles.user_id` -> `users.id`
- `education_records.user_id` -> `users.id`
- `scholarship_category_map.scholarship_id` -> `scholarships.id`
- `scholarship_eligibility_rules.scholarship_id` -> `scholarships.id`
- `scholarship_benefits.scholarship_id` -> `scholarships.id`
- `scholarship_deadlines.scholarship_id` -> `scholarships.id`
- `scholarship_matches.user_id` -> `users.id`, `scholarship_matches.scholarship_id` -> `scholarships.id`
- `saved_scholarships.user_id` -> `users.id`, `saved_scholarships.scholarship_id` -> `scholarships.id`
- `scholarship_applications.user_id` -> `users.id`, `scholarship_applications.scholarship_id` -> `scholarships.id`
- `notification_logs.user_id` -> `users.id`

### Restrictive Deletions (`ON DELETE RESTRICT`)
Ensures transactional safety and historical records:
- `users.role_id` -> `roles.id` (cannot delete roles while users are assigned).
- `subscriptions.user_id` -> `users.id`, `subscriptions.plan_id` -> `subscription_plans.id`.
- `payment_transactions.user_id` -> `users.id` (cannot delete user if they have financial logs).
- `employee_assignments.assigned_by` -> `users.id`.

### Nullified Relationships (`ON DELETE SET NULL`)
Preserves historical records:
- `student_profiles.residence_country_id` -> `countries.id` (if country is deleted, profile country is reset to NULL).
- `scholarships.verified_by` -> `users.id` (if verifying admin is deleted, mark verified_by as NULL).
- `payment_transactions.subscription_id` -> `subscriptions.id`.
- `audit_logs.user_id` -> `users.id`.
- `contact_messages.assigned_to` -> `users.id`.

## 3. Database Indexes

Search optimization indexes are configured on frequently queried columns:
- **`users`**: `email` (Unique), `phone` (Unique), `role_id` (Index), `status` (Index).
- **`scholarships`**: `slug` (Unique), `country_id` (Index), `status` (Index), `verification_status` (Index), `application_deadline` (Index).
- **`scholarship_matches`**: `user_id` (Index), `scholarship_id` (Index), `uq_matches_user_scholarship` (Unique).
- **`subscriptions`**: `user_id` (Index), `status` (Index), `ends_at` (Index).
- **`payment_transactions`**: `transaction_reference` (Unique), `provider_transaction_id` (Unique).
- **`notification_logs`**: `user_id` (Index), `status` (Index), `created_at` (Index).
